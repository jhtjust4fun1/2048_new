# 爆炸 2048：小游戏需求与技术实现文档

## 一、 “爆炸机制”具体设计方案：能量过载 (Overload)

在经典 2048 基础上引入“爆炸”机制，以解决后期空间不足的痛点，并增加风险与收益的策略深度。

### 1. 炸弹的诞生（机制触发）
*   **连击充能**：玩家每次成功合并，界面上方的“能量槽”增加。
*   **生成条件**：当单次滑动触发 3 组以上的连环合并（Combo），或者能量槽满时，下一次生成的将不是普通的 `2` 或 `4`，而是一个**“炸弹方块”**（带有引信的 2 或 4）。

### 2. 爆炸的引爆（合成判定）
*   **基础逻辑**：炸弹方块可以像普通方块一样参与同级合成（例如：炸弹2 + 普通2 = 普通4）。
*   **触发条件**：只要炸弹方块**参与了合成**，就会在合成的瞬间触发爆炸。

### 3. 爆炸效果（AOE 清场与收益）
*   **爆炸范围**：以合成后的新方块为中心，引发 **十字形（上下左右）** 或 **九宫格（3x3）** 的范围爆炸。
*   **清场规则**：范围内所有**小于或等于**当前合成数字的方块会被“炸毁”（数值归零，释放空间）。
*   **保底收益**：被炸毁的方块数值将乘以 2 倍计入总分。中心合成的**新方块免疫爆炸**，保留在场上。

## 二、 核心滑动合并算法实现 (TypeScript)

2048 算法的核心思想是**“降维打击”**。将二维矩阵拆解解为一维数组，统一向一侧“挤压”并合并，然后再组合回二维矩阵。

### 1. 基础数据模型定义

为了方便 UI 动画追踪，数组中存储对象而非纯数字。

```typescript
// 定义每个格子的数据结构
export interface TileData {
    id: number;       // 唯一自增ID，用于UI节点绑定，确保动画能追踪具体方块
    value: number;    // 数值 (0, 2, 4, 8...)，0表示空位
    isBomb?: boolean; // 标识是否为炸弹方块
}

// 初始化 4x4 棋盘
let grid: TileData[][] = Array.from({ length: 4 }, () => 
    Array.from({ length: 4 }, () => ({ id: 0, value: 0 }))
);
```

```typescript
/**
 * 处理单行/单列的滑动合并 (向左靠拢)
 * @param line 包含4个 TileData 的一维数组
 * @returns 挤压合并后的新数组，以及是否发生了合并的标记
 */
function slideAndMergeLine(line: TileData[]): { newLine: TileData[], hasMerged: boolean } {
    let hasMerged = false;
    
    // 1. 提取所有非空方块（去掉0）—— 模拟“滑动”
    let tiles = line.filter(tile => tile.value !== 0);

    // 2. 遍历合并相邻且数值相同的方块 —— 模拟“合并”
    for (let i = 0; i < tiles.length - 1; i++) {
        if (tiles[i].value === tiles[i + 1].value) {
            // 合并：数值翻倍
            tiles[i].value *= 2;
            hasMerged = true; 
            
            // 此处可抛出事件：检测 tiles[i] 或 tiles[i+1] 是否为炸弹，若是则记录爆炸坐标
            
            // 移除被吃掉的方块
            tiles.splice(i + 1, 1);
        }
    }

    // 3. 补齐末尾的空位 (0)
    while (tiles.length < 4) {
        tiles.push({ id: 0, value: 0 });
    }

    return { newLine: tiles, hasMerged };
}
```

```typescript
// 向左滑动
function slideLeft(grid: TileData[][]) {
    for (let row = 0; row < 4; row++) {
        const { newLine } = slideAndMergeLine(grid[row]);
        grid[row] = newLine;
    }
}

// 向右滑动：反转 -> 向左处理 -> 反转恢复
function slideRight(grid: TileData[][]) {
    for (let row = 0; row < 4; row++) {
        let reversedRow = [...grid[row]].reverse();
        const { newLine } = slideAndMergeLine(reversedRow);
        grid[row] = newLine.reverse();
    }
}

// 向上滑动：提取列数据 -> 向左处理 -> 塞回矩阵
function slideUp(grid: TileData[][]) {
    for (let col = 0; col < 4; col++) {
        let columnData = [grid[0][col], grid[1][col], grid[2][col], grid[3][col]];
        const { newLine } = slideAndMergeLine(columnData);
        for(let row = 0; row < 4; row++) {
            grid[row][col] = newLine[row];
        }
    }
}
```

## 三、 UI 与数据动画同步方案

纯算法只改变了内存数据，需要通过以下逻辑实现平滑的视觉表现：

1. **记录状态**：在每次玩家滑动前，遍历记录当前所有非空方块的 `唯一 ID` 及对应的 `(x, y)` 矩阵下标。
2. **执行计算**：运行上述数据层的合并与爆炸算法。
3. **计算位移**：算法执行后再次遍历矩阵。对比方块的 `唯一 ID`。如果 ID 相同但坐标变了，调用游戏引擎的 Tween 动画让该方块平滑移动到新位置。
4. **处理销毁**：如果滑动前存在的 `ID` 在滑动后消失了（被合并或被炸毁），让该 UI 节点位移至目标方块位置（若是合并）或原地停留（若是被炸），随后播放缩放/爆炸粒子动画并销毁节点。
